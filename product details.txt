# 2. Product Philosophy

Autergo should follow five principles.

### 1. Candidate-first access

Candidate does **not need an account**.

### 2. Recruiter-first configuration

HR can configure the entire drive without engineering support.

### 3. Evidence-based AI

AI assists the recruiter. AI should not silently make irreversible hiring decisions.

### 4. Multi-signal proctoring

Never:

```text
Eye movement = cheating
```

Instead:

```text
Multiple signals
        ↓
Suspicion score
        ↓
Evidence
        ↓
Human review
```

### 5. Enterprise-grade auditability

Every important action must be traceable.

# 10. Important Correction: Your Token Design

You proposed:

> Click once → token expires permanently.

I would **not** do this.

Because:

```text
Candidate starts exam
Internet disconnects
Laptop crashes
Browser closes
Power cut
```

Candidate is now locked forever.

That creates a bad enterprise experience.

Use this instead:

```text
Invitation Token
        ↓
Candidate Verification
        ↓
Assessment Session
        ↓
Short-lived Session Token
```

### Example

```text
Invitation Token
   lifetime: days

          ↓

Session Token
   lifetime: assessment duration + grace period
```

The invitation token becomes consumed once the session starts, but the **session itself can resume**.

```text

      ↓
```

# 35. What Redis Actually Does

You said:

> handle server load and database penetration

The more precise explanation is:

Redis helps with **caching, sessions, distributed locks, queues, rate limiting, and high-speed ephemeral state**.

Example:

```text
Candidate Session
      ↓
Redis

Rate Limit
      ↓
Redis

Temporary Assessment State
      ↓
Redis

Job Queue
      ↓
Redis / Queue Broker
```

Don't use Redis as the main permanent database for recruitment records.

```text
       │
       ▼

       │
       ├── Scoring
       ├── Proctor Events
       ├── Analytics
       └── Notifications
```

The API should not do expensive work synchronously.

Bad:

```text

 ↓
Calculate everything
 ↓
Generate AI analysis
 ↓
Write every metric
 ↓
Return
```

Better:

```text
Submit
 ↓
Validate
 ↓
Persist essential data
 ↓
Return success
 ↓
Queue background jobs
```
